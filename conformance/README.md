# Conformance baseline

The golden legacy and v0 transfer messages in `test/test_solana.ml` use the
wire layouts implemented by Agave `v4.2.1`:

- `solana-message` `4.2.3`
- `solana-transaction` `4.1.4`
- `solana-short-vec` `3.2.2`
- `solana-system-interface` `3.2.0`

The vectors deliberately use repeated-byte public keys and blockhashes so every
field and boundary can be inspected directly. The expected bytes are literals,
not output generated by the OCaml encoder during the test. The v0 fixture loads
the writable destination from lookup-table index 1.

`@solana/kit` `8.0.0` is the client-side compatibility target. Ordinary CI is
fully hermetic and does not install Node packages or query an RPC endpoint.

Message version 1 is intentionally absent from the positive fixture set and has
a negative fixture: it remains pending activation at this baseline and its wire
format is rejected explicitly.
